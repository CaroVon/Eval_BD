## Conclusions

1. Screening power follows the parent's near-tie density f_m(0), not its size (Q8_0 |A|/|P|:
   Qwen-3B 0.519, 7B 0.317, 14B 0.398, Llama-8B 0.420). Margin law holds on 40 cases (0.72-1.14).
2. Correction: the decode step time is nearly constant in batch (3B 37 ms, 14B 93 ms); r ~ kappa x
   B_eff is a fixed per-step cost of the batch-invariant engine, not HBM bandwidth.
3. Against valid baselines at equal compute, Q8_0 worst-slice bounds are 2.1-4.2x tighter than B1
   (r = 0.076, b = 0.4) and 1.5-2.1x (r = 0.365, b = 0.6) for all five GSM8K parents (G3 met for
   Q8_0). B2 is always looser than B1; B6 undercovers (0.12-0.74).
4. The dequantization pipeline is faithful (parent perplexity matches llama.cpp to 1e-4), but
   llama.cpp kernels add error beyond the weights.
5. Track B: llama.cpp is repeatable but not prefill/decode consistent unless -ub 1, which removes the
   cost advantage. The certificate is about the canonical batch-invariant execution (Track A). The
   size of the engine gap depends on the model family (Llama 89% identical outputs, Qwen 0.5%).
